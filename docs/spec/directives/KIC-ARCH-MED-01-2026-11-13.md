# KIC-ARCH-MED-01 — Architecture mediation directive — 2026-11-13

**This is a summary, not the verbatim text.** The verbatim directive is in the session record. Priority P0; authority: Project Owner.

## What was asked

Reconcile the intelligence layer against four CopilotKit projects that the earlier baseline had not considered — OpenMuse, OpenDots, OpenDuet and Channels — and return a target architecture and a decision package for owner review.

Positions the directive tells the mediation to preserve unless evidence justifies an approved change:

- OpenBot remains the baseline for agent execution, tool orchestration, isolated computers, permissions, routines, learning and audit. It is not to be replaced because another project looks more attractive.
- The ecosystem relationships it states (OpenDuet built on OpenBot and available as an OpenBot experience; OpenDots available as an experience and as a standalone starter; OpenMuse a separate implementation; Channels a messaging integration, not a publishing engine) are to be verified against source, not assumed.
- Kraken stays independently governed. OpenBot and the other components are capability providers, not owners of execution authority. Kraken's contracts, provider-independent orchestration, approval boundaries, safeguards against repeated business actions, durable state, audit and review gates are preserved.
- Delivery stays a versioned template deployed as separate client-owned instances. No shared multi-tenant infrastructure by default.
- Forward compatibility with Metis, a separate cognitive architecture in development, without depending on it, merging it or starting it.

Workstreams: A baseline audit of this repository; B capability audit of the five upstream projects; C gap analysis; D intelligence and execution boundaries; E Metis compatibility. At least three options to be evaluated (OpenBot with selective augmentation; OpenBot as unified platform with its experiences; a Kraken-owned abstraction with adapters).

Deliverables D1–D7: baseline, capability matrix, gap and opportunity report, target architecture with a diagram, decision package, phased roadmap, minimal proof-of-integration plan.

## Authorised

Inspect this repository; review public upstream repositories and documentation; dependency and licence analysis; comparison documents; proposed decision records; interface designs; non-production proof plans; read-only validation and isolated tests where safe.

## Not authorised

Replacing the current runtime; merging upstream projects into the codebase; changing accepted execution contracts; modifying production infrastructure; activating new external integrations; committing to new paid dependencies; starting the full integration programme before the architecture decision is approved.

## Points recorded on receipt (see the mediation README for detail)

1. The directive calls the system "Kraken Intelligence Core". This repository and its records call it "Kraken Intelligence Companion". Nothing was renamed. Which name stands is for the owner.
2. The directive speaks of an existing intelligence architecture "developed primarily from OpenBot". As recorded: no OpenBot code is in this repository, OpenBot has never been run by this programme, and the foundation decision (OD-1) has not been accepted. The mediation reports the state as it is.
3. The directive lists "exactly-once business-action safeguards" among things to preserve. Kraken's accepted position is that it does not claim exactly-once external execution. The mediation uses Kraken's wording and flags the difference.
4. The directive describes OpenBot as the foundation for execution. Under the accepted separation, external side effects belong to Kraken's execution core, and this repository prepares and never executes. The mediation treats "execution" in OpenBot as agent work inside the preparation boundary and keeps external side effects with Kraken; the target architecture states this explicitly for the owner to confirm or correct.

This directive authorises investigation and documentation. It is not acceptance of any gate or of the foundation decision.
