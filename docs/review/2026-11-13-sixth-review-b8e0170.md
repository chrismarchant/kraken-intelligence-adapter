## Findings

| # | Severity | Finding and evidence |
|---|---|---|
| F1 | high | **A store writer could bring back an approval or a narrative selection that the editor had replaced.** When the editor approved a second draft for a post, the first approval was withdrawn only by resetting a status field; nothing in the signed log recorded it. Setting the first draft's status back to approved and the second's to candidate made the first count again; spoiling the second draft's hash did the same. The decision log, the ledger check and `review` all passed. Probe with the real operator tool: the editor's latest approval for post 1 was one draft; after the status flip, `review`, `release` and `verify` all succeeded with the other. Narratives were affected the same way. This broke the threat model's guarantee that an editorial decision cannot be undone |
| F2 | medium | **Padding let stored text pass for the tool's own lines.** The margin was applied once per stored line; a line padded with spaces to the width of the terminal wrapped, and what followed began in the first column. The probe planted a fake separator and a fake "not published" label inside a post body; the draft passed eligibility. Depends on the attacker guessing the terminal's width |
| F3 | low | The editor signed fields that `show` did not display: a narrative's evidence requirements and risks; a draft's approach and revision links; the planned post's sequencing rationale. `review` printed them before release |
| F4 | low | The stored signature string was not canonical: a re-encoded signature still verified but changed the chain digest, so the operator saw a misleading "rolled back" refusal. Denial of service only |
| F5 | info | Stale locks on the spend account and the ledger were broken on age alone; two processes could both break one. Needs a crashed holder (unproven) |
| F6 | info | A link planted in the export directory had an empty directory created through it before the path check refused (unproven) |

The reviewer confirmed the fifth review's N1, N2 and N3 as closed, and found no way past the budget.

## Remediation (added by the orchestrator)

| # | Change | Regression tests |
|---|---|---|
| F1 | What is approved or selected is read from the signed log alone (`settledByLog`). A decision about a draft carries its post number inside the signature. A post is held by the draft of the latest approval for that post; a later rejection of, or request to revise, that draft empties the post; an earlier approval never returns. Status fields are not consulted. An untrusted log now refuses new requests too | `tests/kic/sixth-review.test.ts` (status flip; spoiled later draft; deleted later draft; rejection; narrative; re-pointed post number) |
| F2 | Stored text is always behind a margin; the tool breaks long lines itself and marks the continuation; runs of spaces are written out; generated text has padding collapsed | `tests/kic/security-review.test.ts` "stored text cannot reach the first column…" |
| F3 | `show` prints every value the request digest covers | `tests/kic/security-review.test.ts` |
| F4 | A signature must be canonical base64 | `tests/kic/sixth-review.test.ts` |
| F5 | The spend account and the ledger use the campaign store's owner-checked lock | `tests/kic/security-review.test.ts` |
| F6 | Exports are created one level at a time and never through a link | `tests/kic/security-review.test.ts` |
