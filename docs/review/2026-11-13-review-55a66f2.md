## Findings

| # | Severity | Finding |
|---|---|---|
| F1 | medium, availability only; **a regression introduced in this commit** | The shim's idle timeout was set once per request, before the host and token checks, adding a listener to the connection each time. On a kept-alive connection they accumulated, each holding its request in memory. Reachable without a token. Probe: 2,001 listeners after 2,000 requests |
| F2 | low | A caller that disconnected while its reservation was being taken left it charged. Errs on the safe side, but a token holder could use up the ceiling without any provider spend |
| F3 | low (not proven exploitable) | The query string of a chat request went upstream unchanged; the allow-list and limits check only the body |
| F4 | info | Writing the body out again can enlarge it, loses precision in very large integers and replaces invalid UTF-8. None increases what a request can spend |
| F5 | low | `displaySafe` did not write out a backslash, so stored text that spells out a code printed exactly like the character the code stands for. The editor still saw every visible character, but could not tell two different texts apart |
| F6 | low (not proven) | Private-use and unassigned characters and enclosing marks passed unchanged; a font that draws them as blanks could let a stored line imitate the continuation marker |
| F7 | info | A pager narrower than the width the tool breaks at can still wrap a stored line; the tool's own wrapping can split an escape across lines |
| F8 | info (not proven) | The concurrency limit counts connections, not generation at the provider; whether the provider's reported completion tokens include reasoning tokens, and whether `max_tokens` bounds them, was not verified offline |
