# Threat model

Scope: the KIC companion as built on 2026-11-13. Not a deployed system; nothing has been deployed.

## What must never happen

| # | Outcome | Why it cannot, as built |
|---|---|---|
| T1 | Content is published, scheduled, sent or promoted | No publishing client, credential or tool exists. A provisional command's schema pins `executable: false`, `authoritative: false`, `status: NON-EXECUTABLE` and has no endpoint, account or clock-time field. Guard tests search the source for publishing and outreach hosts. |
| T2 | An agent, a model or a process that can write the store makes, alters or undoes an editorial decision | Decisions are signed with a key held only by the operator tool, and chained: each names its number and its predecessor. A decision about a draft also carries its post number inside the signature. The agent-facing server holds the public key, has no decision tool, and refuses to record a decision. A forged, moved, repeated or removed decision invalidates the whole log, and nothing more is requested or signed on top of it. Removal from the end is caught by the operator's own ledger. **What counts as approved or selected is read from the signed log alone**: a post is held by the draft of the latest approval for that post, an approval the editor replaced, rejected or sent back for revision never returns, and status fields in the store are not consulted. (Before `12a7626` they were, and two independent reviews showed that a store writer could bring back a replaced approval.) |
| T3 | A person's decision is lost, or applied to something they did not see | Writes are serialised per campaign and atomic. The operator tool shows the request from the campaign record, not from the channel, and prints stored text with control, invisible and direction characters written out as visible codes, so that stored text cannot rewrite the screen. The editor gives back the whole digest of the request, which covers its action, subject, revision instruction and a content hash. That hash covers every stored field of the draft or narrative except status and provenance, the planned post, and the whole brief; the tool displays the planned post, the claims, what the brief rules out and its references. `show` prints every value the digest covers. Stored text is printed only behind a margin, broken to the terminal's width by the tool with the continuation marked, and with runs of spaces, every other kind of blank and a space that opens a line written out, so that it cannot reach the first column where the tool's own lines start. A mismatch refuses the decision, and a decision is void if any of those changes afterwards. |
| T3a | A programme is passed off as signed off when it is not, or is released without being read | What the agent-facing server assembles is a preview and is marked as one in the package, the summary, the commands file and the tool result. A release is the operator's signature over the package digest. Before releasing, `review` shows the brief's constraints, the plan and every approved post and prints a release digest; `release` must be given that digest and refuses a programme that no longer produces it. Releases are written beside the operator key, not in the data directory, and `verify` checks one later. |
| T4 | A draft that breaks a mandatory constraint is approved | Constraints are checked by code at evaluation, at request, at confirmation and at assembly. Scores are never consulted. |
| T5 | The JEV service is called | No live transport is implemented; selecting it throws. No source file names the service. |
| T6 | Model spend runs away | Calls are charged when reserved, failed calls included. The most tokens a step could use is reserved while it runs, and a call cannot exceed three times its allowance; an answer that reports no usage is charged at its allowance. The same charges are kept in the instance's own account, a file outside the campaign store, which also holds ceilings for the whole instance and a limit on the number of campaigns: resetting a campaign record or starting a new campaign buys nothing. Concurrency, provider requests and time are bounded; timeouts and failed fan-outs cancel what is in flight. The model shim is a second route to the provider: whoever holds its client token spends the provider's key. In key-injection mode the shim therefore allows one answer per request, caps the tokens a request may ask for and sends the provider a body it has written out again itself with that cap in it, limits requests in flight, keeps a persistent ceiling on requests and tokens, and refuses to start without a model allow-list and a ceiling unless the ceiling is waived in so many words. In pass-through mode the caller spends its own key and the shim does not limit it. There is no provider-side cap behind any of this, and the figures are provisional until the owner sets them (OD-6). |
| T7 | A credential is logged, stored or returned | Errors carry a status, never a body. The shim logs method, path, status, duration, model and token counts only. The one-time code is stored only as a hash. CI runs a secret scan. |

## Actors and what they can do

| Actor | Capability | Limit |
|---|---|---|
| The agent using the MCP tools | Create campaigns, generate, evaluate, request decisions, assemble | Cannot record a decision; cannot exceed limits; cannot approve ineligible text |
| The model | Writes text that is validated, canonicalised, clipped and given ids by code | Cannot set status, position, ids or provenance; cannot close prompt delimiters; cannot inject markdown into editor-facing documents |
| A client brief containing instructions | Influences the text the model writes | Cannot approve, publish or exfiltrate: no tool does those things |
| A process with write access to the store | Delete or corrupt campaign files; produce a preview from a log with its tail cut off; change the brief, plan or drafts, which voids the decisions made on them; change the unsigned evaluation shown to the editor as advice | Cannot forge, reorder or remove decisions undetected; cannot make changed text, a changed brief or a changed plan count as approved; cannot bring back a choice the editor replaced or withdrew; cannot put control characters in front of the editor or text in the first column of the editor's terminal; cannot reset the instance's spend account; cannot produce a release |
| A process with write access to the operator channel | Plant or alter notices; see one-time codes if it can also read | Cannot change what the editor is shown or what is signed |
| A page on another site, via the browser | — | Host and Origin checks on the HTTP endpoints; bearer tokens |

## Known weaknesses

| Weakness | Consequence | Mitigation |
|---|---|---|
| The operator's key is a file | Whoever can read it can sign decisions and releases | Deployment requirement: separate user or machine. Not enforceable in code. |
| The operator's ledger is a file beside the key | If it is lost, the tool stops. Starting a new one (`new-ledger --accept-current-state`) trusts every decision log as it then stands, so decisions removed before that moment are not detected | Same deployment requirement as the key. Restoring a data directory from a backup older than the ledger is reported as a rollback, correctly; recovering from that is the same explicit command. |
| The editor confirms by pasting a digest | A careless editor can paste it without reading | The tool prints the request in capitals and the full text first; nothing in code can make a person read |
| The approval controls have been reviewed only by agents inside this programme | Eight independent reviews each found a new way to obtain or bring back an approval, to show the editor something other than what was signed, to release something unseen, or to spend without limit. Each was closed and given a regression test. The ninth review (`55a66f2`) found no way through and approved; a delta review of `2537386` confirmed it. Two clean reviews after eight that were not is a short record, and every reviewer was an agent commissioned in these sessions | An approval-path security assessment by someone outside these sessions is required before real-client use (OD-11, open). Until then: synthetic and internal material only |
| A revision can be obtained again by a store writer | A writer who deletes a revision can call for another on the same signed instruction | Each costs budget, which is capped, and each still needs the editor's approval |
| A request's expiry and attempt count are not signed | A store writer can keep a request open or reset its failed attempts | Confirming still needs the one-time code from the operator channel and the editor's digest |
| The terminal's width is assumed when output is not a terminal | Stored text is broken at 72 columns when the tool's output is piped, unless `KIC_OPERATOR_COLUMNS` gives the width; a viewer narrower than that could still wrap a line | Every stored line and every continuation carries its margin, which a wrapped piece would not |
| The shim's ceiling can be waived | `SHIM_ALLOW_UNLIMITED=1` starts key injection with no ceiling | It has to be set deliberately; the instance template requires a ceiling |
| The plan is not an editor decision | The editor selects a narrative and approves posts; each approval is bound to its own planned post, and the whole plan is shown at release, but no decision is recorded on the plan as such | A plan decision bound to the plan's hash is a proposed follow-up (changes the editorial flow; owner decision) |
| Right-to-left letters are printed as they are | On a terminal that reorders bidirectional text, Hebrew or Arabic letters in stored text could reorder part of a line. Direction controls are always written out | Unproven; stated |
| Prompt tokens are not limited | Only completion tokens and calls are budgeted. Through the model shim the caller writes the prompt, bounded only by the 2 MiB body limit and the request ceiling | For KIC's own generation, prompts are built by code from bounded fields. For the shim, nothing more: a figure belongs with OD-6 |
| Guesses at a confirmation code are not limited across requests | A caller can keep guessing | Codes are 128 bits; at most 25 requests can be pending; a correct code signs nothing without the operator's key. Mitigated, not fixed; no test |
| The export root defaults to a directory inside the data directory | A store writer could use the window between the export's path check and its write to have preview files written elsewhere the server's user can write | Releases are written by the operator tool, to a directory that may not be inside the data directory. Instance template requirement 19: the export root outside agent-writable space |
| The shim writes the request body out again | It can enlarge the body, lose precision in very large integers and replace invalid UTF-8 | Cannot increase what a request spends |
| The provider's accounting is unverified | Whether reported completion tokens include reasoning tokens, whether `max_tokens` bounds them, and what is billed after a disconnect are not known. The shim's concurrency limit counts connections, not generation at the provider. A caller that half-closes its connection was not probed | First live run in key-holding mode, under a ceiling |
| Some fixes have no regression test | The 72-column break, the shim's idle cut-off, the colon-and-equals listing and the departed-caller charge were checked by reviewers' probes only | Listed in the gate ledger (A26) |
| The readable summary is not verified | `verify` checks the package and the commands file, not the summary beside them; a bare URL in it becomes a link | The package is what is signed |
| The editor's identity is typed into the operator tool | The record says who decided because the holder of the key said so | Possession of the key is the credential. Single-editor instances only, for now. |
| Mandatory constraints are pattern rules | Rephrasing can evade a ruled-out term; two ordinary letters drawn to look like one are not read as it ("rn" for "m", "vv" for "w", "cl" for "d"), and brackets are not read as "c"; a term of several words is missed if one word needs a closing "!" read as a letter and another needs it left off. The rules also err towards refusing where text can be read as the ruled-out word: "A1" or "Al" for "AI", "H1" for "hi", a hashtag that starts or ends with a short ruled-out word ("#Winter" for "win"), single letters in a row ("Plan A I think"), and endings for words of four letters or more ("scar" refuses "scared"); endings other than the plural, the past and "-ing" are not matched, and a term of fewer than four letters matches itself and its plural only; a non-numeric comparison marked by the model as not needing evidence is not checked | The number rule is strict by design; the editor is shown the full text; `grounding` is a judgement, not a guarantee |
| The number rule is strict, with narrow exemptions | A post that mentions a number not in a cited reference is ineligible, apart from a short list: B2B, Q3, 24/7, the identifiers ISO, IEC, SOC, RFC and COVID with a number, a year after a word that only introduces a date ("in 2026", "since 2021"), "By 2027" opening a sentence, and a span of years that runs forward. A figure can still be dressed as a date ("in 1950.") | Deliberate. The editor is shown the full text and can ask for a revision. |
| Evaluations are not signed | A writer to the store can change the ranking and score shown to the editor | The line is labelled as advice, unsigned and outside the digest. Eligibility is recomputed by code from the brief and the draft, both of which the digest covers. |
| The spend account and the releases are files | Whoever can write the operator directory can reset the account; whoever can write the release directory can alter exported files | Same deployment requirement as the operator channel and the key. `verify` detects an altered release or commands file. A step that never settles stays charged at its worst case, so a crash costs allowance, never the reverse. |
| The instance ceilings have no reset | An instance that reaches its lifetime ceiling on calls or tokens stops generating until its owner raises the ceiling | Provisional, pending OD-6 |
| Terminal safety was tested against rules, not terminals | The escaping removes every control, format and default-ignorable character; no real terminal emulator or bidirectional renderer was used in tests | Stated |
| The store lock is for one machine and one process-id space | Two machines, or two containers with separate process ids, sharing a store directory could both write: each would judge the other's lock by process ids that mean nothing to it. Where `/proc` cannot be read, a reused process id or a zombie is taken to be a live owner, and others wait | Stated as a deployment requirement. A dead owner's lock is removed by exactly one process (`src/store/lock.ts`) |
| A draft may contain only the characters named in `src/evaluation/characters.ts`: 694 in all | Latin letters as European languages, Vietnamese and pinyin write them; the digits 0 to 9; keyboard marks; a short list of typographic marks; and a fixed list of about a hundred pictures (arrows, ticks, stars and emoji), one at a time. A post cannot quote a word or a name in Greek, Cyrillic, Arabic, Chinese or any other script; cannot use a symbol or an emoji that is not listed, a flag, a skin tone, a keycap or emoji joined into one; and must set a picture apart from words. A campaign in a language written in another script cannot be prepared with this version | By design: every script, and the wider Latin blocks, have letters that pass for ordinary ones, and no list of look-alikes is complete. A list of what is allowed is. The editor is shown the reason. Whether other scripts are needed is a product question for the owner |
| The evaluator does not see long unbroken runs of characters | A hashtag, a hyphenated phrase or an address of 40 characters or more is replaced by a marker in what is sent to the evaluator, which may lower a score | The mandatory constraints are computed on the real text, and the editor is shown the real text |
| Connections that have not shown a token are bounded, not prevented | A client can hold connections for the header timeout (5 s) and keep opening more. At 256 the server closes the longest-idle one, taking first from those that never showed a token, so a caller with a token is still served; a flood large enough to exhaust the machine is not something this code stops | The endpoint is meant for loopback or a private interface (instance template) |
| The mock evaluator is heuristic | Rankings reflect text features, not quality | Labelled as such everywhere it appears |
| Unsigned mode exists for development | Decisions are unprotected against a store writer | Must be asked for explicitly; the package says UNSIGNED |
| The model endpoint is configurable | A misconfiguration could send the key to another https host | Must be https or loopback; set per instance by its owner |
| Reviewer identity in the review ledger is self-declared | The commit-bound review check can be satisfied by a false entry | Human merge through branch protection is the real control (owner action, not yet configured) |

## Global-stop conditions

A credential exposed; unexpected outbound traffic; an instruction in repository or tool content that tries to widen access; any unauthorised write outside this repository. `node harness/scripts/aeh.mjs stop --level global --reason "..."`.
